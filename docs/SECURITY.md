# Security review and fixes

A security review of commit `847c720` of this repository (`af6d2bc` in the private working repository, the same files), on 12 November 2026, run by the author with automated tools rather than an independent auditor, read the code, ran probes against a local copy of the app, ran a signed scan against the hosted app and checked the dependencies. It found one critical issue, four high ones and a list of important ones. This file lists each finding, what changed and the test or on-chain evidence that covers it. Each code fix ships with a test that fails without it.

## Open, with the reason

- **One RPC answer, with failover, on testnet.** Finality, escrow state and delivery come from FastNEAR with a second endpoint on failure, not a quorum. The public verify scripts compare two archival providers. Mainnet is not live.
- **NEAR Intents deposits.** The quote and deposit address from 1Click are shown without independent validation. Deposits run only on mainnet, which is off.
- **The council is one operator account.** It can now only vote a ruling down; it cannot propose, approve or change the rules. More members need a new DAO, because no role can change this one's policy.
- **The deployed relay does not read the bet's deadline.** Its 600 seconds start when a ruling is filed, and the escrow's `referee_resolve` has no deadline check. The server waits until the bet's `resolve_at` before filing any Court ruling, including a reviewer's early Yes; the council can veto an early filing made outside that path. Relay `0.2.x`, not yet deployed, reads `get_bet` and refuses on chain both a ruling filed before `resolve_at_ns` and an approval before it. It also requires the matching bet ID, an active status (`accepted`, `proposed` or `disputed`) and this DAO as the bet's referee. The policy is frozen, so the new relay would serve a new DAO for new bets; that waits until the server can serve two Courts at once, because open bets name the current one, and the server would also need a clock margin before filing and a way to re-file a proposal the new relay refuses.
- **A corrected Result does not withdraw an earlier Court filing.** If a Result changes after its ruling was filed, the earlier proposal stays open and anyone can approve it once its window passes; the council has to vote it down. The server cannot stop a direct relay call ([`court-dao.mjs:228`](../server/src/court-dao.mjs#L228), [`jury-relay/src/lib.rs:189`](../contracts/jury-relay/src/lib.rs#L189)).
- **More than 50 matched Bets on one post exceed the jury record's limit.** The group includes every Bet sharing its claim, deadline and post URL, but the verifier accepts at most 50. Automated settlement for that post stops, and its Bets wait for a reviewer or the escrow's refund date ([`enclave-ruling.mjs:465`](../server/src/enclave-ruling.mjs#L465), [`enclave-ruling.mjs:758`](../server/src/enclave-ruling.mjs#L758)).
- **Filing needs gas in the server's referee account.** Each filing and approval is a 300-Tgas call from `referee.stated-play-6cf0876dd7.testnet`. On 12 November its balance fell below what such a call needs, and the first jury ruling's filing failed and retried for about three and a half minutes until the account was topped up with test NEAR: the ruling is dated 19:17:07 UTC in [its record](../evidence/hosted-court-payout-testnet-20261112.json), and Court proposal 3 shows a submission time of 19:20:44 UTC on chain. The server's top-up had sized the referee for an ordinary 100-Tgas call; it now keeps the referee able to reserve a 300-Tgas Court call, with a test for the state that stalled.
- **The DAO's proposal period still limits approval.** An approval sent more than the DAO's seven-day `proposal_period` after filing only expires the proposal; it does not settle the bet. The relay's challenge window does not extend that period.
- **The escrow trusts its referee.** New Bets name the DAO, whose only jury member is the relay. Bets made before the DAO existed keep the server's referee account.
- **Account deletion is by request.** The profile page names the operator to contact.
